## Architecture: BROWSER CAPTURE + SERVER INFERENCE  (supersedes any "on-board edge" design)
- The classroom browser opens the web app, grants camera access (getUserMedia), and streams
  downscaled JPEG frames over a WebSocket to the backend.
- The Python/FastAPI backend runs the vision pipeline and streams results back.
- Frames are processed IN MEMORY and NEVER persisted.

## What this system is
1. Attendance: frame -> SCRFD detect -> IoU/ByteTrack track -> ArcFace re-ID per track on an
   interval -> cosine match vs enrolled embeddings -> presence state machine -> Supabase.
2. Proctor (exam): YOLOv8n phone/extra-person + head-pose flags + gaze-down suppression filter.
   Every flag -> human review queue. Never auto-penalise. (Phase 3)
3. Engagement (VNEI): behavioural signals (head pose, eye-closure, phone, stillness) aggregated
   to class/zone level with visibility normalisation. NEVER per-student. (Phase 3)

## Non-negotiable invariants (violating these = wrong code, even if it works)
- **No model training.** ArcFace/SCRFD/YOLO are pretrained. We ENROL (compute embeddings) and
  MATCH. No fine-tuning pipelines. Enrolment target: 10-20 quality frames/student (not 50).
- **Embeddings-only identity.** Raw enrolment video/frames deleted immediately after embedding.
  Live frames discarded after inference. Never persist raw face images.
- **Privacy tiers.** T1 attendance = per-student (consented). T2 engagement = class/zone
  aggregates only, suppress any aggregate with n < 5. T3 trainer pulse = ephemeral.
  There is NO per-student engagement score anywhere (schema, API, UI).
- **No emotion labels.** Behavioural signals only. Never "happy/bored/confused".
- **Human-in-the-loop.** Proctor flags are review-queue items, never penalties.
- **Audit chain.** Attendance-affecting writes append to the hash-chained audit_log.
- **Right to delete.** Deleting a student purges embeddings + identity rows (cascade) + audit entry.

## Vision backend abstraction (important)
`backend/vision/base.py` defines Detector/Embedder/Matcher protocols. Two implementations:
- `stub` (vision/stub.py): deterministic, dependency-free. Runs in CI and on any machine; a
  solid-colour card acts as a "face". USE FOR TESTS.
- `insightface` (vision/insightface_backend.py): real SCRFD + ArcFace (buffalo_l). Install with
  `pip install -e '.[insightface]'`; select with `VISION_BACKEND=insightface`.
Depend only on the protocols. Never import a concrete backend outside the factory in pipeline.py.

## Targets
- ID accuracy >=90% (<=4 m) MVP, >=95% full; presence-duration error <=8 min/60 min MVP.
- Frame->dashboard latency <4 s MVP; proctor FPR >=50% reduction with gaze-down filter.

## Do NOT
- Add Kubernetes/Kafka/microservices/native mobile/federated learning/liveness-v2. Module ceiling 10.
- Store per-student engagement, emotion labels, or raw face images.
- Train anything. Merge agent code without a human review.

## Run
- Backend (stub): `cd backend && pip install -e '.[dev]' && uvicorn app.main:app --reload`
- Enrol: `sensepro-enroll --student-id s1 --video clip.mp4 --out enrollments.json`
- Capture client: open `web/capture.html`, set server to ws://localhost:8000/ws/capture
- Tests: `cd backend && pytest -q`
- Production vision: `pip install -e '.[insightface]'` then `VISION_BACKEND=insightface uvicorn ...`
